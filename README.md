# TRE Stocks — Serverless Stock Movers Pipeline

This project implements a **fully serverless stock analysis pipeline** on AWS. It automatically computes the **highest‑moving stock each trading day**, stores results in DynamoDB, exposes them through an API, and displays them on a static frontend.

The system is built end‑to‑end using **Terraform**, **AWS Lambda**, **EventBridge**, **DynamoDB**, **API Gateway (HTTP API)**, and **S3 static website hosting**.

---

## Architecture Overview

**Daily Flow (Automated)**

1. **EventBridge (cron @ 4:00 PM EST)** triggers a Lambda.
2. **Compute Lambda** fetches market data from the Massive/Polygon API.
3. The Lambda computes the **single biggest mover of the day**.
4. The result is stored in **DynamoDB** (one item per trading day).

**On‑Demand Flow (Frontend)**

1. A static website hosted on **S3** loads in the browser.
2. Frontend JavaScript calls **API Gateway**.
3. API Gateway invokes a second Lambda.
4. That Lambda returns:

   - 1 most recent trading day (featured)
   - Next 7 most recent trading days (past movers)

5. The frontend renders the results.

## Tech Stack

- **Infrastructure as Code:** Terraform
- **Compute:** AWS Lambda (Python 3.14)
- **Scheduling:** Amazon EventBridge (cron)
- **Database:** DynamoDB (on‑demand)
- **API:** API Gateway (HTTP API, $default stage)
- **Frontend:** HTML / CSS / JavaScript

## Dependencies and External Packages

This project is intentionally designed to **avoid third-party Python dependencies** so that Lambda deployment remains simple and reproducible.

### Backend (AWS Lambda)

The Lambda functions use **only Python standard library modules** and the AWS SDK that is **preinstalled in the Lambda runtime**.

No `pip install` steps are required.

Used modules include:

- `boto3` (provided by AWS Lambda)
- `json`
- `urllib.request`
- `datetime`
- `zoneinfo`
- `functools`

Because of this design choice:

- There is **no `requirements.txt`**
- There is **no virtual environment setup**
- Terraform can zip the backend directory directly

### Frontend

The frontend uses **plain HTML, CSS, and JavaScript**.

No frameworks, bundlers, or package managers are required.

You do **not** need:

- Node.js
- npm / yarn
- Any external JS libraries

### Infrastructure

Terraform automatically downloads required providers during:

```bash
terraform init
```

No manual provider installation is necessary.

## Step 1 — Store API Key in Secrets Manager

Create a secret in **AWS Secrets Manager**:

- Name: `dev/massive-api-key`
- Value (JSON format recommended):

```json
{
  "MASSIVE_API_Key": "YOUR_API_KEY_HERE"
}
```

Terraform references this secret via the environment variable:

```
MASSIVE_API_SECRET_ARN
```

## Step 2 — Infrastructure Deployment (Terraform)

All AWS resources are defined in `infra/main.tf`.

From the `infra/` directory:

```bash
terraform init
terraform apply
```

Terraform will create:

- S3 bucket (static website hosting)
- DynamoDB table
- IAM roles and policies
- Lambda functions
- API Gateway HTTP API
- EventBridge scheduled rule

Terraform outputs:

- `frontend_website_url`
- `api_base_url`

## Step 3 — Lambda Functions

### 1. `compute-todays-movers` (Scheduled Lambda)

**Triggered by EventBridge daily at 4:00 PM EST**

Responsibilities:

- Determine the latest completed trading day
- Fetch open/close prices for predefined symbols
- Compute percent change
- Select the **single biggest mover**
- Store result in DynamoDB

Important features:

- Uses **New York timezone** for market logic
- Handles weekends automatically
- Throttles API calls to respect rate limits
- Supports manual backfill via CLI (`market_date` override)

---

### 2. `get-previous-movers` (API Lambda)

**Triggered on demand by API Gateway**

Responsibilities:

- Scan DynamoDB
- Sort items by date (newest → oldest)
- Return **8 items total**:

  - 1 featured (latest)
  - 7 past trading days

This design ensures:

- Weekends/holidays do not break the UI
- Oldest day drops automatically when new data arrives

---

## Step 4 — EventBridge Schedule

The daily schedule is defined as:

```hcl
cron(0 21 * * ? *)
```

Explanation:

- 21:00 UTC = **4:00 PM EST**
- Runs once per trading day after market close

The rule appears under:

```
EventBridge → Scheduled rules (legacy)
```

---

## Step 5 — Frontend (S3 Static Website)

The frontend is a static website hosted on S3.

### `app.js` Responsibilities

- Call the API Gateway endpoint
- Sort returned data defensively
- Display:

  - Featured "Current Highest Stock"
  - Past 7 trading days vertically

The frontend automatically:

- Excludes the featured day from the past list
- Drops the oldest past day when a new day arrives

---

## Step 6 — Manual Backfill (One‑Time)

To populate historical data, the compute Lambda supports a CLI override.

Example — backfill **January 22, 2026**:

```bash
aws lambda invoke \
  --function-name compute-todays-movers \
  --cli-binary-format raw-in-base64-out \
  --payload '{"market_date":"2026-01-22"}' \
  /tmp/out.json
```

Notes:

- Wait ~60 seconds between runs to avoid API rate limits
- DynamoDB stores results permanently

## Data Model (DynamoDB)

Each item represents **one trading day**:

| Attribute        | Description               |
| ---------------- | ------------------------- |
| `date`           | Trading date (YYYY‑MM‑DD) |
| `symbol`         | Stock ticker              |
| `percent_change` | Daily percent move        |
| `close`          | Closing price             |
| `fetched_at`     | UTC timestamp             |

## Common Pitfalls (and How They Were Solved)

- **Weekends causing missing days** → Return latest stored items instead of calendar math
- **Rate limits (HTTP 429)** → Throttling + retries
- **CORS errors** → Explicit headers in API Lambda
- **Terraform not detecting file changes** → `etag = filemd5(...)` on S3 objects
